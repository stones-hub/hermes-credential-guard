# R11 / 0.4.5 —— 开箱可用性与保护边界透明化 方案

**状态**：C1–C9 本机技术候选已实施；C10 离线 `validate` CLI 已落地（本机源码候选）。C8–C9 专项已绿；版本升至 0.4.5 / 构建 / 正式 Profile 安装仍未做。
**基线**：`2d4c25d`（plugin.yaml `version: 0.4.4`；当前为未提交的本机候选工作树）
**日期**：2026-08-20
**性质**：以可用性、可诊断性和文档准确性为主。C1 是唯一触及失败分支的改动，但按已批准的 B 方案只放行“配置目录从未创建”这一档；凭证来源、审批绑定、白名单及其余 fail-closed 判据不变。

---

## 一、为什么要做这一版

0.4.4 的安全能力经实测确认扎实：已登记凭证六种编码形态全部防住、注入全程审批、越界全拒、回流双向脱敏。

但**产品此前是按「作者自用」打磨的，不是按「陌生人开箱」打磨的**。插件即将开放给外部用户，当前存在三类问题：

| 类别 | 后果 |
|---|---|
| 装完即砖 | 新用户装完插件、还没建配置文件，**整个 Hermes 不能聊天** |
| 安全错觉 | 用户以为「装了就安全」，实际只保护手工登记过的凭证 |
| 失败不说话 | 所有错误塌缩为两个不说明原因的出口，其中一个名字还在撒谎 |

目标：**让没读过源码的人装上插件后，不会把 Hermes 弄坏、知道自己被保护了什么、犯错时知道怎么改。**

## 二、0.4.4 实测基线（本方案的事实依据）

### 2.1 保护边界实测（27 例，判据为「该用例自身的秘密是否仍在模型上下文」）

**已登记凭证 —— 六种编码全防住**

| 形态 | 结果 |
|---|---|
| plain / percent / quote_plus / base64 / urlsafe_b64 / json_escape | 全部替换为 `<SECRET:cg_xxx>`，真值零残留 |

来源：`redactor.py:47 build_secret_variants()` 为每条登记凭证构造六种可逆编码变体做匹配。

**未登记凭证 —— 零保护，原样通过**

| 用例 | 自身真值仍在上下文 | 内容变化 |
|---|---|---|
| OpenAI `sk-proj-…` | 是 | 否 |
| GitHub `ghp_…` | 是 | 否 |
| AWS `AKIA…` | 是 | 否 |
| AWS Secret Key | 是 | 否 |
| Slack `xoxb-…` | 是 | 否 |
| MySQL 连接串密码 | 是 | 否 |
| JWT | 是 | 否 |
| `password=xxx` | 是 | 否 |

源码中**不存在**任何通用凭证格式识别器。除私钥外无启发式检测。未登记 = 无变体 = 无匹配 = 放行。

**私钥 —— 替换，不阻断**

| 形态 | 模型看到 | 请求是否发出 |
|---|---|---|
| raw PEM / OPENSSH | `<REDACTED_SECRET>` | 发出（`model` 未被改写） |
| percent / base64 编码 | `<REDACTED_UNRESOLVED_SENSITIVE_FIELD>` | 发出 |

注：0.4.2 为本机阻断，0.4.4 已改为整字段替换后继续。历史结论需按版本区分。

**对照组无误伤**：普通中文、订单号、git sha、普通 base64 数据均原样通过。

### 2.4 引用语法错误的行为

参数 `credential=<SECRET:cg_xxx>`（插件自己盖的脱敏代号）：


### 2.5 两条路径占位符（C9 已统一为保守形态）

| 路径 | 同一凭证的占位符 |
|---|---|
| `llm_request`（用户粘贴） | `<SECRET:cg_…>` — 死代号 |
| `transform_tool_result`（工具读到文件） | `<SECRET:cg_…>` — 同一死代号 |

**决策（C9）**：反向统一为更保守的 registry token `<SECRET:cg_[0-9a-f]{16}>`。不得把用户粘贴或工具回流升级成模型可执行的 `<CREDENTIAL:name>` 逻辑引用；正式工具参数仍只接受 description 中列出的 `<CREDENTIAL:name>`。

## 三、改动清单

### 批次一：装完能用（P0）

#### C1. 零配置不再变砖

**现状**：配置文件不存在 → `RuntimeConfigError` → 全线 fail-closed → 普通聊天不可用。

**改为**：区分两种失败。

| 情况 | 处理 | 理由 |
|---|---|---|
| 配置目录（store dir）**不存在** | 视为「插件从未配置」，放行；首次加载时打一行本地提示 | 全新安装用户尚未运行 migrate / CLI，配置目录根本不存在；这一档没有文件凭证来源，但进程内已登记凭证、私钥和敏感路径保护仍必须生效 |
| 配置目录存在、配置文件**不存在** | 维持 fail-closed | 这是已开始配置但未完成的半配置态；与承重安全测试的既有约束一致，不静默放行 |
| 配置文件**存在但非法** | 维持现有 fail-closed | 用户已声明要保护某些凭证，读不出来就宁可断 |
| 配置合法但 `bindings` 为空 | 已正常工作（见 2.3），不变 | — |

**安全论证**：放行必须精确绑定到配置目录本身的 `FileNotFoundError` 专用 code，不得使用合并后的 `RUNTIME_CONFIG_NOT_FOUND`，否则会把「目录存在、文件缺失」也错误放行。放行分支仍复制并使用进程内基础注册表，且继续执行私钥检测和敏感路径保护。解析异常、权限异常、IO 异常及半配置状态一律不得进入放行分支。

**必须的反例测试**：
- 文件存在但内容为空 → 仍阻断
- 文件存在但权限不可读 → 仍阻断
- 文件存在但 JSON 非法 → 仍阻断
- 目录存在、文件不存在 → 仍阻断
- 配置目录不存在 → 放行
- mutation：把「不存在」判定改成 catch-all `except Exception` → 上述前三条必须 RED

#### C2. 配置错误给出可操作诊断

**现状**：`code=CG-CONFIG-UNAVAILABLE`，不说哪个文件、哪条 binding、哪个字段。

**改为**：本地日志补充定位信息。

```
Credential Guard 配置加载失败，已进入保护性阻断。
文件：<配置文件绝对路径>
问题：binding "<名称>" 含未知字段 "<字段名>"
改法：删除该字段后重试
```

**硬约束**：
- 只写本地日志（stderr / Hermes 日志），**不进入模型上下文**
- **不得回显任何凭证值、username、password、header 值**
- 字段名、binding 名可显示（它们是用户自己写的结构标识，非秘密）
- 诊断信息本身需过一遍现有脱敏器，防止用户把凭证误写进 binding 名

#### C3. 修复文档示例 Bug

`docs/R3-通用本地凭证注入-落地方案.md:165-166` 与 `:200-201` 的示例含 `allowed_tools` / `reference_arg_path` 两个 schema 禁用字段。照抄该示例会导致整个配置文件被拒、插件全线 fail-closed。

**改为**：删除这四行。这两个字段由 `runtime_config.py:139-151` 从 binding 类型自动推导，**永远不应出现在用户配置中**。

同时检查全仓库文档中是否存在其它含禁用字段的示例。

#### C4. README 头部写死保护边界

在 README「主要能力」之前插入边界声明：

```
保护：
  - 配置文件中登记过的凭证（明文 / URL 编码 / Base64 / JSON 转义等六种形态）
  - 私钥（PEM，会被替换为占位符）

不保护：
  - 未登记的凭证 —— 原样发送给模型
  - 自动标题、上下文压缩、图片识别、session_search 等辅助模型调用
```

同时补充「最小可用配置」章节：只写 `credentials`、`bindings` 留空即可获得脱敏保护（依据 2.3 实测），让用户先跑通再逐步加 binding。

### 批次二：用着顺手（P1）

**状态**：C5–C7 已获用户批准并完成本机实现。分项结果：C5 规格/安全复审 PASS；C6 专项与安全复审 PASS；C7 首轮复审发现空 `session_id` 去重条目可能被普通 Session LRU 淘汰，已按严格 TDD 窄修为独立、最多四项的进程级 family 集合，关闭复审 PASS。当前进行 C1–C7 最终候选身份冻结与集成复审。详细实施任务书：仓库内 `.c5c7-usability-task.md`（被 `.gitignore` 忽略，仅供本机委派执行）。

#### C5. 工具描述在插件注册时列出可用目标

**现状（修正前）**：若在 `register()` 中直接 `ensure_published_from_disk()`，冷启动虽能列出 binding，但会读取完整统一配置并构建 egress registry，违反「审批前/普通工具注册不读凭证明文」门禁。

**架构修正**：新增插件自动生成的安全目标清单旁车 `credential-guard.targets.json`：

- `credential-guard.json` 仍是唯一真配置（含秘密）。
- 旁车只保存模型可见字段：binding 名、`type`、`credential_ref`、HTTP `allowed_methods`/`allowed_paths`；禁止 host/port/program/argv/env/header/secret/digest 等。
- 由 `hermes credential-guard refresh-targets`、正式配置写入 helper（`replace_config_and_refresh_targets`）或迁移成功后自动生成；用户不手工维护旁车。
- Hermes 启动注册工具时**只读旁车**，并对主配置仅做 `lstat` 身份比对（shared flock 覆盖 identity→读旁车→identity 复核）；不一致/缺失/非法 → 静态 description fallback；旁车绝不进入 `runtime_config._PUBLISHED`，也不能作为执行依据。
- 正式 egress/审批/执行继续走原 `runtime_config`。
- `replace_config_and_refresh_targets`：主配置已提交但旁车失败时抛固定部分提交错误 `CONFIG_COMMITTED_TARGET_CATALOG_UNAVAILABLE`；目录 fsync 为 best-effort，不宣称崩溃持久性强保证。

**约束**：
- 只暴露 binding 名、credential 名、允许的 method/path —— 这些是「本机允许什么」的声明，不是秘密
- **不得暴露** host、port、程序绝对路径、argv、env_name、任何凭证值
- 配置变更后：先 `refresh-targets`，再重启 Hermes；README 必须如实写明
- 删除 `R3A` 等内部代号
- 任一 credential/binding 名等于任一 token/password 明文时，Schema 必须 fail-closed（防描述泄漏）
- 任一 token/password 明文若为模型可见字符串（binding 名、被引用 credential 名、HTTP method/path）的子串，同样 `CONFIG_SCHEMA` fail-closed
- 旁车 HTTP method/path 校验与正式主配置契约一致（allowlist、去重、数量上限、`validate_exact_http_path`）；`version` 必须是整数 `1`（拒绝 `true`）

**状态**：C5–C7 已获用户批准；本轮完成旁车架构修正。

#### C6. 引用语法错误明确报错

**现状**：`credential=<SECRET:cg_xxx>` → 判定 `no_reference` → 静默跳过审批 → `RUNTIME_ADAPTER_NOT_READY`。

**改为**：识别出参数值是插件自己盖的脱敏代号，返回明确错误：

```
CREDENTIAL_CODE_NOT_USABLE
提供的是脱敏代号，不是凭证引用。凭证不能通过对话传入。
可用目标：<清单>
正确写法：credential=<CREDENTIAL:<凭证名>>
```

**约束**：
- 只改错误信息与错误码，**不改变放行/阻断判定**
- 该分支仍然不执行、不注入、不弹审批（因为确实没有合法引用）
- 不得因识别代号而反查出对应的真实凭证名并自动替换 —— 那等于代号还原，明确禁止

#### C7. 未登记凭证提示（不拦截）

**现状**：未登记的 key 原样进入模型上下文，用户无感知，容易形成安全错觉。

**改为**：新增一个**只读检测器**，识别常见凭证前缀格式，命中时打本地提示：

```
⚠ 检测到疑似未登记的凭证，它不受 Credential Guard 保护。
  要保护它，请加入 <配置文件路径>
```

**硬约束（关键）**：
- **放行行为零变动**。不阻断、不脱敏、不改写请求内容。纯提示。
- 只写本地终端/日志，**不进入模型上下文**
- **不得输出被检测内容本身**，连片段和哈希都不输出
- 检测器抛异常时静默跳过，**绝不允许因提示逻辑导致请求失败**
- 每个 session 对同一形态最多提示一次，避免刷屏

**诚实性要求**：该检测**注定不完整**。有明显前缀的（`sk-`、`ghp_`、`AKIA`、`xoxb-`）能认；纯随机串（AWS Secret Key、内部系统 token、数据库密码）认不出。README 与提示文案必须表述为「可能遗漏」，**严禁**宣传为兜底能力。误报（如长订单号被当作 key）可接受，代价仅为多一行提示。

### 批次三：干净度（P2）

#### C8. 错误码更名与死代码清理

- `RUNTIME_ADAPTER_NOT_READY` 字面意思为「适配器未实现」，但 HTTP / process 适配器均已实现且实测可用。该字符串来自 `runtime_config.py:445 require_runtime_adapter()`，全仓库无生产调用点。
- 删除该死代码，改用如实反映失败原因的错误码（审批失败 / plan 校验失败等分开）。
- 参数越界类已有独立码 `HTTP_REQUEST_REJECTED`，保持不变。

#### C9. 统一两条路径的占位符形态 — **已落地（保守统一）**

`llm_request` 与 `transform_tool_result` 对同一凭证曾给出不同占位符（见 2.5）。评估后采用更保守方案：

- 两条路径均输出 registry `CredentialValue.token`：`<SECRET:cg_[0-9a-f]{16}>`
- **不**统一成 `<CREDENTIAL:name>`：用户粘贴主请求不得升级成模型可执行逻辑引用
- 正式工具参数中的 `<CREDENTIAL:name>` 引用语义不变；把回流代号当作 `credential` 仍返回 `CREDENTIAL_CODE_NOT_USABLE`

#### C10. 离线配置校验命令 — **已落地**

提供插件 CLI 子命令 `hermes credential-guard validate [<file>]`：逐 credential、逐 binding 输出 `PASS`；失败输出 `FAIL <固定错误码> <安全定位>`（不可安全定位时为 `configuration`）。

- 显式 `file` 只读该文件；缺省使用 `default_config_path()`。
- 校验过程不要求当前运行配置有效，不 publish RuntimeView、不生成旁车、不写任何文件、不调用 Provider/adapter。
- **纯插件限制**：命令需插件代码已被 Hermes 加载/启用后才能由宿主发现；不要求（也无法在纯插件接口下做到）插件 disabled 时宿主仍能发现该命令。
- stdout/stderr 不含凭证值、host、program、argv、env/header 名、allowed path、JSON 正文或异常正文。

## 四、明确不做

| 提议 | 拒绝理由 |
|---|---|
| 支持从对话中读取 `apikey:xxx` 作为凭证来源 | 凭证来源必须是本机配置。接受对话内容即意味着模型（及任何能influence模型上下文的内容，如网页、PDF、issue）可决定使用哪个凭证 |
| 支持模型指定 `baseurl` 作为发送目标 | 等价于让模型决定「把凭证发给谁」。prompt injection 可直接指使外发到攻击者地址 |
| 代号还原：把 `<SECRET:cg_xxx>` 换回真值塞进 shell 命令 | 真值进入进程参数 → `ps`、shell history、日志、错误信息全部泄漏。且同样让模型间接决定发送目标 |
| 配置错误改为「只禁用出错的 binding」 | 出错的 binding 可能是唯一登记某凭证的位置，隔离它会让该凭证失去脱敏保护而裸奔。文件级 fail-closed 是 `docs/R1B-单文件正式运行链路切换-实测报告.md:120-133` 固化的有意设计 |
| 未登记凭证直接拦截 | 检测必然不完整且必然误报，误报会打断正常工作。收益（部分覆盖）远小于代价（不可预测的中断） |

## 五、安全影响逐条对照

| 改动 | 是否触及安全判据 | 说明 |
|---|---|---|
| C1 零配置放行 | **是（唯一一处）** | 仅在「无配置文件 = 无登记凭证」时放行；需完整反例 + mutation 门禁 |
| C2 配置诊断 | 否 | 只写本地日志，不回显凭证值，诊断信息本身过脱敏器 |
| C3 修文档 | 否 | 纯文本 |
| C4 README 边界 | 否 | 纯文本，且是把现状如实写出 |
| C5 工具描述列目标 | 否 | 暴露的是「本机允许什么」的声明，非秘密；真值仍在本机 |
| C6 引用报错 | 否 | 只改错误文案与错误码，判定逻辑不变，仍不执行不注入 |
| C7 未登记提示 | 否 | 放行行为零变动，纯提示，检测器异常时静默跳过 |
| C8 错误码更名 | 否 | 改标识符 + 删无调用死代码 |
| C9 统一占位符 | **是（保守收紧）** | 工具结果改为死代号，消除「回流可用引用」；正式 `<CREDENTIAL:name>` 参数路径不变 |
| C10 离线校验 | 否 | 只读校验，不加载凭证值 |

**不变的三条铁律**：
1. 凭证真值只能来自本机配置文件
2. 每次注入必须人工审批，一次批准只消费一次
3. 模型永远拿不到凭证真值

### C1–C4 本机技术签收（2026-08-20）

- **结论**：PASS。C1 按 B 方案落地；C2 为 code 级本地中文诊断，并已补可安全定位的字段位置（`credentials.<id>` / `bindings.<id>[.<白名单字段>…]`，非法名降级 `configuration`）；C3、C4 完成。

## 七、附：本方案修正的历史错误结论

实测过程中发现并已修正的错误认知，记录以防再次引用：

| 错误结论 | 实际 | 成因 |
