## 1. 为什么要收口

R5 第一步是建立三类门禁：旧架构残留扫描（residue auditor）、路径增删改账本（signed topology）、禁止构建的测试 runner（no-build runner）。

五轮下来的事实：

| 轮次 | 修复内容 | 复审结果 |
|------|----------|----------|
| Round 1 | 建成三类门禁 | 7 类假绿 |
| Round 1A | 关闭 7 类假绿 | 7 个新增路径 mutation 被 pytest.skip |
| Round 1B | 去掉 skip | 4 类新假绿（常量变量、敏感路径读取、runner 未强制、mutation 被无关错误掩盖） |
| Round 1C | 关闭 4 类 | 控制流分支、闭包改写、builder 动态成员、读取别名、pytest 环境注入 |
| Round 1D | 关闭上述 | 36 条 auditor MISSED + 19 条 runner BYPASS |

这不是实现质量问题，是问题形状问题。「用静态分析证明任何写法都不能把旧架构偷回来」是开放问题——每轮换个 Python 语法就能再找一条。与 R3C 的假绿死循环同形，那次最终靠换策略（canonical AST 冻结）而非继续枚举才收口。

## 2. 收口原则

两类门禁性质不同，分别处理。

### 2.1 no-build runner：架构改造，不是补检测

当前设计是「允许调用者传任意 pytest 参数，然后用静态分析证明 build_all 不可达」。19 条 BYPASS 全部源于这个设计。

改为两条硬边界：

**边界一：收回选择权。** runner 不接受任何调用者提供的测试选择参数（路径、nodeid、目录、`-k`、`--ignore`）。只跑内部固定语料。调用者只能传经允许的显示类参数（`-q`、`--tb`、`-p no:cacheprovider`）。任何未知参数 fail closed。

**边界二：运行时绊线。** runner 设置进程环境变量（如 `CG_NO_BUILD_TRIPWIRE=1`）；`build_all()` 函数入口第一件事就是检查该变量，命中则立即抛异常。

绊线是关键：无论 payload 藏在哪个模块、用什么语法绕过静态扫描，**构建实际发生的瞬间**就失败。这把开放的静态分析问题换成了封闭的运行时问题。

静态传递扫描保留，但降级为辅助提示，不再是唯一保证。

### 2.2 residue auditor：明确威胁模型边界

auditor 要防的是：

- 删除不彻底（漏了某个模块、依赖、声明）
- 以后有人**无意**把旧架构改回来

不防：对抗刻意混淆的本地作者。理由——恶意本地作者能直接改门禁本身，这条防线在威胁模型里不成立；Credential Guard 的威胁模型是「外部模型不得接触凭证」，从不包含恶意本地作者。

按此边界，方案中明确声明：

> residue gate 覆盖直接形式与编译期可解析形式。无法静态解析的动态值，在关键 sink（工具注册、动态导入、旧双文件读取、builder 成员定义）上一律 fail closed。刻意构造的混淆绕过不在门禁职责范围内。

## 3. 必修项（结构性缺陷 + 误判）

以下属于「正常写法就会漏」或「门禁不可用」，必须修。

### 3.1 循环回边无 fixpoint（12 条 MISSED 的共同根因）

`scripts/audit_legacy_residue.py` `visit_For` L1275-1292 / `visit_While` L1296-1311 只跑 zero + once 两条路径，循环体内被赋值的名字在 **body 之后**才 invalidate（L1283-1284、L1304-1305），第二次迭代的绑定永不回灌。

```python
def install(reg):
    tool = "safe_tool"
    for _ in range(2):
        reg.register_tool(name=tool)      # 第二次迭代注册的是旧工具名
        tool = "mysql_credential_action"
```

正式 `audit_tree()` 返回 `[]`。

覆盖 sink：`register_tool`、`dynamic_import`、`path_read`（Path 对象重绑定）、f-string 拼名、模块作用域、嵌套循环、walrus、`while True` + break/continue、`for` + `try/except/else`。

**修法：** 进入 body 之前先用 `_collect_assigned_names(node)` 把循环体内所有被赋值的名字 invalidate；或迭代到不动点（body 至少复访两遍）。

### 3.2 绑定读别名只认零参调用（7 条）

L1508 的 `and not node.args and not node.keywords` 导致带参调用漏检。

```python
p = Path("credentials.json")
reader = p.read_text
return reader(encoding="utf-8")     # kinds: []
```

同类：位置参 `opener("rb")`、`o(mode="rb")`、`r(*args)`；别名存入 dict/list/`self` 后取出调用（L802-836 `_apply_assignment` 只处理 `ast.Name` 目标）。

**修法：** 去掉零参限制。`_apply_assignment` 对 `Subscript`/`Attribute`/容器字面量元素中命中 `_bound_read_from_value` 时 fail closed 报 `unresolved_dynamic_sink`。

### 3.3 register_tool 只看 `name=` 关键字（5 条）

L1515-1518 遍历 `node.keywords` 找 `name`，遗漏：

- 位置参：`reg.register_tool("mysql_credential_action", fn)`
- `**kwargs` 解包：`opts = {"name": "..."}; reg.register_tool(**opts)`（`kw.arg is None` 被 `!= "name"` 跳过，未 fail closed）
- 导入常量：`register_tool(name=LEGACY_NAME)`（L1526 `_is_dynamic_unresolved` 对 `missing` 状态 Name 返回 False）
- 绑定别名：`rt = reg.register_tool; rt(name=...)`（L1505 只看字面 attr/name）
- 推导式 target：`[reg.register_tool(name=n) for n in names]`

**修法：** `node.args[0]` 也做 `_resolve_str` / fail-closed；`kw.arg is None` 直接 `_note_unresolved_sink`；`missing` 状态 Name 在 register_tool sink 上 fail closed（与 dynamic_import L1547-1551 已有处理对齐）。

### 3.4 读白名单按裸符号名匹配，影子命名可冒用（3 条）

`_enclosing_symbol` L395-401 只取最近一层函数名，`_dual_file_read_allowed` L985-996 不校验嵌套层级与类归属。任意函数内嵌一个叫 `_read_secure_bytes` 的内层函数即获白名单：

```python
def migrate_config(base):
    def _read_secure_bytes(_):
        return (base / "credentials.json").read_bytes()
    return _read_secure_bytes(None)
```

同类：`class Anything` 的 `_read_secure_json` 方法、`class Shim` 的 `_read_secure_bytes` 直接 `open()`。

注：顶层公开读入口（`read_v1_credentials` 真实读旧文件）**已被正确捕获**，白名单本身对顶层有效，漏的是影子命名。

**修法：** `_enclosing_symbol` 返回带层级的限定名（`migrate_config._read_secure_bytes` / `Shim._read_secure_bytes`），白名单只匹配模块顶层函数（函数层数为 1 且无 ClassDef 祖先）。

这一条与 3.7 的误判是同一根因的两面。

### 3.5 builder 路径判定过窄（1 条）

`_is_builder_path` L924-931 要求文件名含 `build`。`scripts/package_dist.py` 里的 `MEMBERS = ["credential_guard/tools.py", "deps/pymysql"]` 完全静默。

**修法：** 扩到所有 `scripts/*.py`，或增加 `package|dist|release|wheel|sdist` 关键词；对 `deps/pymysql` 与 `OLD_MODULES` 字面量做 `scripts/` 级全面检查。

### 3.6 函数默认参数从未被访问（1 条）

`_visit_function_like` L1170-1204 只 visit decorator / returns / body，不 visit `args.defaults` 与 `args.kw_defaults`。

```python
def inner(data=Path("credentials.json").read_bytes()):
    return data
```

**修法：** 在**外层 env** 下补 visit `args.defaults` + `args.kw_defaults`。

### 3.7 误判噪声过高（阻塞门禁可用性）

`audit_tree(REPO)` 当前返回 **520 条**，其中大量是 `unresolved_dynamic_sink at path_read`，命中的是干净生产代码：`adapters/http.py`、`adapters/process.py`、`config.py`、`config_lock.py`。原因是任何参数派生的路径读取一律 fail closed。

后果：真正开始删除时，真实告警会被噪声淹没，门禁失去判别力。

另有 `H4_clean_nested_helper_in_private_reader`：白名单读入口 `_read_secure_bytes` 内的私有嵌套 helper `_slurp` 被误报（`_enclosing_symbol` 取最内层名，丢掉白名单归属）。

**修法：** 收窄 `unresolved_dynamic_sink` 判定——只在路径值可能指向旧双文件时 fail closed（例如涉及 `_STORE_BASENAMES` 相关常量、旧文件名片段、或来自迁移输入的参数），普通派生路径读取不再判红。同时 3.4 的限定名修复会一并关闭 `_slurp` 误报。

## 4. 明确划到边界外（写入方案，不再追）

以下需刻意绕才会写出，且 §2.2 的 fail-closed 兜底声明覆盖其风险：

| 类别 | 示例 |
|------|------|
| 间接调用取函数 | `getattr(importlib, "import_module")("tools")`、`importlib.__dict__["import_module"](...)` |
| 字符串导入 | `exec("from credential_guard import tools", ns)` |
| 别名经容器/属性中转 | 别名存 dict/list/`self` 后取出调用（若 3.2 的 fail-closed 已覆盖则自然关闭） |
| 文件外泄 API | `shutil.copy(str(base / "credentials.json"), dest)` |
| spec loader 变体 | `spec_from_file_location` / `module_from_spec` 组合的动态载入 |

注：`spec_from_file_location` 与 `copy` 类 API 若实现成本低，可顺手纳入 sink 名集合与 `PATH_READ_ATTRS`；但不作为收口阻塞项。

## 5. no-build runner 的 19 条 BYPASS（全部由 §2.1 结构性关闭）

全部经正式 runner 子进程验证：sentinel 文件真实被创建、pytest 真实启动、构建真实执行。**不是仅看退出码。**

批次一（8 条）：相对导入各层级、`from tests.pkg import mod` 后属性链调用、fixture 链多跳、`credential_guard` 包内多层 helper 等。

批次二（6 条）：

- `v_exec_local_var_fixed` — exec 局部变量 payload
- `v_eval_local_var_fixed` — eval 同形
- `v_nodeid_selection` — 直接传 nodeid 选择
- `v_dotslash_prefix` — `./` 前缀路径绕过归一化

批次三（5 条）：`--` 之后配合 `-k` / `--tb` inline / `-p` value / `--maxfail` / `-x` 各形式携带选择。

额外一条最刺眼：

- `v_existing_modified_module_no_new_files` — payload 藏在**已有语料模块**内，不新增任何文件。topology 门看不到（无路径变化），preflight 也未拦住。

已确认 RED（正确拦住）：`v_rel_level1_same_pkg`、`v_dotdot_relpath`、conftest 注入、entry-point 插件、`PYTEST_ADDOPTS`、`PYTEST_PLUGINS`、同目录 helper、包 submodule 别名。

**根因：** `main()` 在 argv 校验后调用 `preflight_no_build()`，但 preflight 依赖静态可达性分析，且调用者仍能决定选择集。§2.1 的两条边界同时消除「调用者控制选择」与「静态分析是唯一保证」这两个前提。
