# Credential Guard 0.4.3 Release Notes

## Highlights

- Long-session continuity: large cumulative chat requests no longer false-block solely due to total size.
- Actionable local block messages with reason / location / code / next step — Provider is not called.
- History residual and scanner-boundary recovery: quarantine recoverable history and continue in the same Session.
- Ordinary dynamic-key collisions rename to unique safe keys and continue.
- Boundary-unknown encoded private keys in content-class fields are whole-field redacted on the Provider-bound copy only.
- Narrow hardening: protocol/skeleton fields (`model`, `role`, `name`, `tool_call_id`) fail closed instead of whole-field placeholder forwarding.

## Fixes

- Protocol-field whole-field fallback narrowing (observation from the long-session final review).
- Session continuity stack from today’s R9 workstream packaged as the 0.4.3 release candidate.

## Security invariants

- Real secrets stay in the local protected store; Provider-bound copies never carry them.
- Canonical Session is never mutated by redaction/recovery — only the outbound copy is.
- Manual approval remains required before local credential injection.
- No second permission catalog; target-system permissions remain the source of truth.
- Synthetic/decoy values only in tests and examples.

## Install / upgrade

Use the designated plugin ZIP from GitHub Releases (after Tag/Release) or the local `dist/` artifact:

```text
credential-guard-0.4.3-hermes-plugin.zip
```

Follow the fail-closed install blocks in the repository `README.md` (SHA-256 check, structure check, version pin, then enable). Keep `approvals.mode: manual`.

Historical `0.4.2` artifacts remain in `dist/` for comparison; do not overwrite `v0.4.2`.

## Verification (release candidate)

See `docs/R9-0.4.3-验收报告.md` for measured commands, counts, artifact hashes, and isolated ZIP E2E. Formal worker install is intentionally not performed by the release-candidate agent.

## Known boundaries

- Does not cover Hermes `auxiliary_client.call_llm` paths (title / compression / vision / oneshot / session_search, etc.).
- Does not claim OS-level DLP; local logs/WAL may retain plaintext in the trusted zone.
- HTTP/HTTPS credential request behavior from 0.4.2 is retained.
