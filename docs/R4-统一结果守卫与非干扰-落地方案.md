# R4 统一结果守卫与非干扰落地方案

> 日期：2026-08-04  
> 状态：**已完成并正式签收（2026-08-05）**  
> 上位真源：`Credential-Guard-最终项目目标.html`  
> 前置状态：R0–R3 已签收，R4 不回改其安全语义

## 1. 一句话定义

R4 是工具结果进入模型上下文前的统一出口安检：能安全脱敏就保持真实结果的格式和业务含义直接返回；不能确认安全就阻断原文，并且不虚构工具成功、失败或回滚。

## 2. 与最终目标的精确对应

R4 只闭合最终目标中的两项：

1. **STEP 6 / STEP 7**：检查 stdout、stderr、异常、Header 和支持的编码变体；守卫失败时不把原始内容回传，模型只看到安全结果。
2. **非干扰**：普通聊天、文件、Git、terminal、SSH Config、Docker/systemd、编码、测试和日志排障能力不受插件影响。

R4 不负责 R5 旧架构清理、R6 发布构建、正式 worker 升级，也不扩大为通用 DLP 平台。

## 3. 最小主链

```text
工具真实结果
→ Hermes 正式 transform_tool_result Hook
→ 一个权威结果守卫
→ 必要的定点脱敏
→ 对最终待发送结果做零残留复查
→ 通过：按原格式交给模型
→ 失败：用固定安全文本替换整份原文
```

所有正式工具共用同一标准。HTTP/process 可保留执行边界的第二道保险，但必须调用同一权威规则，不得继续维护 `***`、整份丢弃等不同脱敏语义。

## 4. 放行语义

### 4.1 干净结果

完全不修改，直接返回：

- 文本仍是原文本；
- JSON 不重排字段、不改缩进、不压成一行；
- 日志、Markdown、表格、中文、数字、布尔值、错误码和退出信息保持不变；
- 不增加审批，不改变工具是否执行及其副作用。

### 4.2 已登记凭证

真实值及项目已支持的可逆编码变体，替换为稳定逻辑代号：

```text
<CREDENTIAL:credential-name>
```

只替换命中片段，其余内容和排版不动。

### 4.3 未登记的高置信度秘密

只覆盖明确、有限的高置信度边界：

- `Authorization`、`Proxy-Authorization`；
- 认证用途的 `Cookie`、`Set-Cookie`；
- 明确的 `password`、`token`、`secret` 键值；
- 私钥 PEM 及现有检测器支持的编码形态。

可安全定位字段值时，替换为：

```text
<REDACTED_SECRET>
```

认证 Header/Cookie 采用整段值替换。若私钥或编码材料只能判断“存在”而无法可靠定位完整范围，则整份结果失败关闭，不为局部保留强行增加复杂解析器。

### 4.4 明确不误伤

不因“长、随机、像编码”而处理以下普通内容：

- Git commit SHA；
- 文件或制品 SHA-256；
- UUID；
- Request ID、Trace ID；
- 普通 Base64 数据；
- 端口、IP、路径和日志编号。

## 5. 异常结果

异常与正常结果走同一规则：

- 保留真实异常类型、错误码、Request ID、Trace ID 和安全的排障正文；
- 只替换秘密；
- 不把失败改成成功；
- 不声称动作已经回滚；
- 不隐藏“工具可能已产生副作用”的事实。

## 6. 失败关闭

只有以下情况才整体阻断：

- 结果守卫自身异常；
- 无法确认实际待发送内容已被完整检查；
- 脱敏后的最终零残留复查失败。

固定安全文本为：

```text
工具可能已经执行，但返回内容未通过安全检查，原始结果未返回。请独立核验目标系统的真实状态。
```

阻断后：

- 绝不自动重试；
- 不断言工具成功或失败；
- 不虚构回滚；
- 如需继续，先用只读方式核验目标系统真实状态。

## 7. 大结果

不预建流式扫描平台。

R4 检查 Hermes 实际交给 Hook、准备进入模型上下文的完整字符串：

- 内容大不是阻断理由；
- Hermes 已经截断且不会外发的部分不属于 R4 外发面；
- 当前 Hook 仍提供完整字符串时，直接做有界完整扫描；
- 用大字符串和敏感值位于首部、中部、尾部的测试证明完整覆盖；
- 只有未来宿主接口真实变成流式回传时，才单独设计跨块扫描，不提前实现。

## 8. 凭证生命周期

不新增独立“结果快照仓库”。

- Hook 使用当前统一配置产生的 registry 快照；
- HTTP/process 在本次 `SecretLease` 关闭前，调用同一权威结果规则处理适配器输出；
- 由适配器把本次 credential 名与短期真值作为函数参数传入，不落盘、不入日志、不进入审批或模型上下文；
- Hook 再次执行必须幂等；
- `SecretLease` 仍按 R3 既有生命周期关闭，不新建持久状态、TTL 或并发清理系统。

## 9. 日志

不建设 R4 独立日志系统：

- 正常放行不记录；
- 正常脱敏不记录；
- 不记录原始结果、替换片段、凭证真值、映射或敏感异常正文；
- 仅守卫自身异常并阻断时，复用 Hermes 现有日志记录固定告警和不含业务内容的安全原因码。

## 10. 生产代码边界

建议最小结构：

- 新建 `credential_guard/result_guard.py`：唯一权威识别、替换、零残留复查和固定失败文本；
- 收窄 `credential_guard/hooks.py`：只做 Hook 参数归一化、受保护路径前置阻断和调用权威守卫；
- 修改 `credential_guard/adapters/http.py`、`credential_guard/adapters/process.py`：移除各自不同的 `***` / `PROCESS_OUTPUT_LEAK` 产品语义，改为复用权威守卫；
- 复用 `credential_guard/redactor.py` 的已登记凭证变体能力；
- 复用 `credential_guard/sensitive_paths.py` 的私钥检测能力；
- 不修改 Hermes 核心，不新增第三方依赖。

## 11. 非干扰矩阵

必须证明：

- 普通聊天和无凭证工具结果原样；
- 文件读写、搜索结果原样；
- Git status/diff/log 和 commit SHA 原样；
- pytest、编译输出和制品 SHA-256 原样；
- terminal、execute_code 正常输出原样；
- SSH Config/loopback SSH 样例的安全结果可用；
- Docker/systemd 只在隔离参数和合成输出上验证，不连接真实目标；
- JSON、Markdown、表格、中文、Request ID、Trace ID、UUID、普通 Base64 不误伤；
- 大字符串首、中、尾均完整检查；
- 不增加审批，不修改真实文件、数据库、目标状态、退出码或副作用。

## 12. 严格边界与非目标

R4 不做：

- 第二套审批；
- 自动重试或自动回滚；
- 独立日志、审计数据库或运营统计；
- 通用云密钥/JWT/Webhook 规则库；
- 仅凭随机度判定秘密；
- OS 级 DLP；
- 修改真实文件、数据库或目标系统；
- 修改 Hermes 核心；
- 连接真实目标、读取真实凭证或真实 `~/.ssh`；
- R5、R6 或 worker 升级。

## 13. R4 完成定义

只有同时满足以下条件才可签收：

1. 正式 PluginManager 注册的真实 `transform_tool_result` Hook 进入唯一权威守卫；
2. 已登记凭证及支持编码变体在最终结果与 Provider 原始请求中计数为 0；
3. 高置信度认证字段和异常栈正反例通过；
4. 守卫异常和残留 mutation 均返回固定安全文本；
5. 阻断不触发自动重试，不虚构成功、失败或回滚；
6. 非干扰矩阵通过；
7. R0–R3 回归和全量测试 0 failed；
8. 稳定候选冻结后，Cursor 与两路 Hermes 最终只读复审全部 PASS；
9. 正式 Hermes 源码、正式 worker、历史 0.3.1 `dist/` 均未修改。
