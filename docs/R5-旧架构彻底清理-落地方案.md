# R5 旧架构彻底清理落地方案

> 状态：待用户评审；只读盘点已完成，尚未删除代码或进入 R5 实施。
>
> 上游基线：R0–R4 已正式签收。R4 技术候选为 `283 / 29059 / 226fb1999179d17020ed2f05d7834cfaa63279d294ada3c64d3de9620d29717e`；R3 历史 sidecar 与 0.3.1 历史制品保持冻结。

## 1. 一句话结论

R5 不是重写 Credential Guard，而是把已经由通用 HTTP/env/stdin 链路取代的旧 MySQL/SSH 固定动作从当前生产源码和未来制品中彻底拿掉，同时保留单文件运行、旧配置迁移、SSH Config 非干扰和全部 R0–R4 安全能力。

## 2. 为什么现在可以清理

旧架构提供四个写死动作：

- MySQL：`check_connection`、`show_effective_grants`
- SSH：`check_connection`、`show_remote_identity`

它们在早期用于证明“模型不知道凭证，也能由本机在审批后执行受控操作”。现在这项安全性质已由配置化链路覆盖：

- HTTP Header：`http_credential_request`
- 固定程序 env/stdin：`credential_process_run`
- 审批绑定、TOCTOU、一次性 consume：R2/R3 已签收
- 统一结果守卫与非干扰：R4 已签收

继续保留旧动作不会增加新的保护能力，只会让产品中同时存在两套入口、两套配置语义和一套只服务 MySQL 的依赖。

## 3. R5 范围

### 3.1 本轮必须完成

1. 生产插件只注册 `http_credential_request` 与 `credential_process_run` 两个通用工具；
2. 删除旧 MySQL/SSH 固定动作、专用 executor、专用审批分支；
3. 删除 vendored PyMySQL、依赖钉死和旧依赖完整性代码；
4. 旧双文件不得再成为运行时工具、审批或外发数据源；
5. 保留 `migrate-config`，旧双文件只允许作为显式一次性迁移输入；
6. 建立语义化 residue gate，证明旧架构没有进入当前生产源码与候选包；
7. 删除或迁移只验证旧产品行为的测试与脚本；
8. R0–R4 回归、全量、内存编译和非干扰必须保持绿色。

### 3.2 明确不做

- 不构建或覆盖 `dist/`；
- 不确定新版本号；
- 不生成最终 wheel/sdist/plugin ZIP；
- 不修改最终目标 HTML；
- 不访问正式 Profile、真实 `~/.ssh`、真实凭证或真实目标；

### 4.2 需要先解耦再删除的共享点

#### A. `TOOLSET_NAME`

`reference_tools.py` 和 `process_tools.py` 目前从旧 `tools.py` 导入 `TOOLSET_NAME`。R5 先新建职责单一的 `credential_guard/constants.py`，只放：

```python
TOOLSET_NAME = "credential_guard"
```

两个通用工具和 `credential_guard/__init__.py` 改从该模块导入，之后才能删除 `tools.py`。

#### B. 默认配置目录

旧 `default_store_dir()` 位于 `tools.py`，但正式单文件运行已有权威入口 `runtime_config.default_config_path()`；迁移已有独立 `migration.resolve_config_dir()`。

R5 不把旧路径 helper 搬成兼容壳：

- 正式运行继续只用 `runtime_config.default_config_path()`；
- 迁移继续只用 `migration.resolve_config_dir()`；
- 删除旧动作后，其他生产代码不得再需要 `default_store_dir()`。

#### C. `file_backend.py`

整个模块是旧 `credentials.json + targets.json` v1 运行时 backend。清理后正式运行不应 import 它。

但 `migration.py` 目前从中复用 v1 schema 常量和 SSH alias 校验。为避免保留整套旧 backend：

1. 把迁移所需的最小 v1 schema 定义与校验移入 `migration.py` 内部；
2. 保留严格字段集、SSH alias 安全规则、0600/0700、nofollow、owner 与事务恢复合同；
3. 删除 `file_backend.py`；
4. residue gate 允许 `credentials.json` / `targets.json` 只出现在 `migration.py`、迁移测试、敏感路径保护和历史文档中。

这不是删除迁移能力，而是把“旧运行时 backend”收窄成“显式迁移输入解析器”。

#### D. `ssh_config` 单文件类型

当前 `credential-guard.json` 仍允许 `ssh_config` credential/binding，但 R3 通用执行分发只实现 `http`、`process_env`、`stdin`；`ssh_config` 不会执行注入，且普通 SSH Config 本就应走 Hermes `terminal`，不需要 Credential Guard 代执行。

R5 决定：

- 从当前 v2 正式 Schema 删除 `ssh_config` credential/binding；
- `ALLOWED_BINDING_TYPES` 只保留 `http`、`process_env`、`stdin`；
- `ALLOWED_CREDENTIAL_TYPES` 只保留 `token`、`username_password`；
- 迁移遇到旧 SSH target 时与旧 MySQL 一样返回 `MIGRATION_REQUIRES_MANUAL_REVIEW`，不自动生成一个无法执行的 v2 binding；
- 普通 SSH、SSH Config 和私钥路径非干扰/敏感路径保护继续保留。

原因：不能为“迁移成功”制造一个当前产品无法执行的正式配置。

复审分歧记录：一条只读审计建议把它暂时保留为“迁移兼容数据类型”；另一条指出它没有当前消费者，属于潜在孤儿 Schema。经主代理对 `tool_execution.py` 和 `injection.py` 的实际分发复核，当前执行器确实只支持 HTTP/env/stdin，`ssh_config` 无可执行适配器。因此采用后者：R5 删除正式类型，但完整保留普通 SSH 非干扰与私钥路径保护。

## 5. 目标生产结构

R5 完成后的 `credential_guard/` 只保留四类能力：

1. 外发保护：`middleware.py`、`state.py`、`registry.py`、`redactor.py`、`sensitive_paths.py`；
2. 单文件配置与迁移：`config.py`、`bindings.py`、`runtime_config.py`、`migration.py`、`config_lock.py`；
3. 审批后通用注入：`references.py`、`tool_request.py`、`approval.py`、`injection_plan.py`、`tool_execution.py`、`injection.py`、HTTP/process adapters；
4. 结果守卫与工具入口：`result_guard.py`、`hooks.py`、`reference_tools.py`、`process_tools.py`、`cli.py`、`constants.py`。

普通 SSH Config 不由插件注册固定动作，继续由 Hermes 原有 terminal/OpenSSH 使用；Credential Guard 只保证相关普通能力不受影响、私钥路径不被模型读取。

### 6.4 Mutation

每类 gate 必须有负向 mutation：

1. 在临时候选的 `plugin.yaml` 重新加入旧工具，gate 必须失败；
2. 新增生产文件 import `mysql_executor`，必须失败；
3. 在临时 `pyproject.toml` 加回 PyMySQL，必须失败；
4. 在临时候选创建 `deps/pymysql/__init__.py`，必须失败；
5. 让 runtime_config 回退 `credentials.json`，必须失败；
6. 删除迁移 allowlist，历史双文件迁移测试必须失败，防止“清理”误删迁移能力。

## 9. 风险与防护

### 风险 1：误删迁移能力

防护：先把迁移需要的最小 v1 parser/validator 内聚到 `migration.py`，再删 `file_backend.py`；保留全套迁移事务、恢复和 mutation。

### 风险 2：把普通 SSH 能力一起删掉

防护：只删插件的固定 SSH 工具和 executor；保留 `sensitive_paths.py`、SSH Config 非干扰测试、terminal/OpenSSH 普通路径。

### 风险 3：历史测试被直接删除后丢失安全性质

防护：先将仍通用的性质迁到 R0–R4 测试或 residue gate，再删旧文件；历史报告和冻结制品原字节保留。

### 风险 4：R5 顺手变成发布轮

防护：不改版本、不覆盖 dist、不生成正式制品。构建脚本仅做源码适配和静态测试，双构建与最终 ZIP 归 R6。

### 风险 5：粗暴字符串扫描误伤历史证据

防护：residue gate 按“生产注册/import/包成员/运行时读路径”做语义判断，历史文档和迁移输入有窄 allowlist；不以全仓零字符串为目标。
