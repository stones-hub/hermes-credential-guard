# M0/M1 插件骨架与外发命门验证方案

## 目标

先用最小代码验证：独立插件能否在不修改 Hermes 源码的前提下，拦截当前 Hermes 的真实模型外发请求，并保证诱饵秘密不进入 HTTP 请求体。

本里程碑不实现真实文件/MySQL凭证，不安装到当前 worker Profile，不读取任何真实密码。

## 技术选择

- Python 3.11+
- Hermes general plugin API
- pytest
- Python 标准库 HTTPServer 作为本地假模型服务
- PyYAML 仅用于 manifest/后续文件后端；M1 不依赖业务凭证文件

## 编码任务清单（委派前需用户审批）

### 任务 1：建立插件骨架和加载测试

创建：

```text
plugin.yaml
__init__.py
credential_guard/__init__.py
credential_guard/state.py
credential_guard/cli.py
tests/test_plugin_registration.py
```

行为：

- 插件名为 `credential-guard`。
- 注册 `llm_request`、`llm_execution`、`transform_tool_result`。
- 注册 `hermes credential-guard check`。
- `check` 只输出状态和拦截点，不输出秘密。

TDD：先写注册失败测试，确认 RED，再实现至 GREEN。

### 任务 2：实现诱饵凭证注册表和精确脱敏

创建：

```text
credential_guard/models.py
credential_guard/registry.py
credential_guard/redactor.py
tests/test_redactor.py
```

行为：

- 测试注册表只接受测试注入的凭证结构。
- 对请求中的 dict/list/tuple/string 递归复制，不修改原对象。
- 精确值替换为 opaque 稳定引用 `<SECRET:cg_<hash>>`（与 key/field/secret 解耦）。
- 长值优先替换，避免短值破坏长值匹配。
- 空值和过短值拒绝注册，避免误伤普通文本。
- 日志和异常中不出现原值。

TDD 正反例：纯文本、嵌套 JSON、Authorization、DSN、重复值、重叠值、空值、短值、原对象不变。

### 任务 3：实现外发请求双层保护

创建或修改：

```text
credential_guard/middleware.py
tests/test_request_guard.py
```

行为：

- `llm_request` 生成脱敏后的完整请求副本。
- `llm_execution` 在调用 `next_call` 前再次扫描。
- 正常请求只调用一次 `next_call`。
- 检测到仍有诱饵原值时，不调用 `next_call`。
- 内部异常时返回安全阻断响应或安全请求，不携带原始现场内容。
- 不依赖抛异常实现阻断，因为 Hermes 中间件异常默认失败放行。

TDD negative test：主动注入 redactor 异常，断言下游网络调用次数为 0。

### 任务 4：实现工具结果提前脱敏

创建或修改：

```text
credential_guard/hooks.py
tests/test_tool_result_guard.py
```

行为：

- `transform_tool_result` 对字符串和 JSON 字符串脱敏。
- 不改变工具结果的 JSON 可解析性。
- 失败时返回不含原工具内容的安全错误结果。

### 任务 5：建立隔离 Hermes 真实 HTTP 捕获测试

创建：

```text
tests/fake_provider.py
tests/test_hermes_canary_e2e.py
scripts/run_canary_e2e.py
```

行为：

- 创建临时 `HERMES_HOME`。
- 将插件链接或复制到临时 `plugins/credential-guard`。
- 启用插件。
- 启动本地假 OpenAI-compatible HTTP 服务。
- Hermes 对假服务发起真实模型请求。
- 捕获原始 HTTP 请求体。
- 断言诱饵值出现次数为 0、稳定引用存在。
- 断言插件日志和临时 session 存储不含诱饵值。

如果 Hermes 真实会话在进入插件前已持久化原始用户内容，测试必须如实标红，不能通过清理测试数据掩盖。

## 明确不做

- 不读取当前用户真实 `.env`、SSH 私钥、Cookie 或业务配置。
- 不修改 Hermes 源码。
- 不安装到当前 worker Profile。
- 不实现文件后端和 MySQL 后端。
- 不实现本地安全执行器。
- 不创建 Git 仓库。

## 验收标准

| 编号 | 标准 |
|---|---|
| AC1 | 插件在隔离 Hermes 环境中被发现并启用 |
| AC2 | `llm_request`、`llm_execution`、`transform_tool_result` 均注册成功 |
| AC3 | 实际 HTTP 请求体中诱饵原值出现次数为 0 |
| AC4 | 脱敏后稳定 opaque 引用存在且不包含原值片段 |
| AC5 | redactor 主动异常时下游网络调用次数为 0 |
| AC6 | 请求对象本地原件不被原地改写 |
| AC7 | 工具结果脱敏后仍是合法 JSON |
| AC8 | 日志中不出现诱饵原值（按零明文架构门禁；当前因无统一 fail-closed pre-persist seam 预期红） |
| AC9 | 本机 session/state 零明文（待用户拍板是否降为“仅披露残余风险”；拍板前保持红灯） |
| AC10 | 所有专项测试退出码为 0（架构门禁单独 xfail，不混称全绿） |

## AC8/AC9 seam 说明

Hermes v0.19.0 没有覆盖 CLI、Gateway、ACP、TUI、cron、subagent 等所有 agent 入口、受支持且 fail-closed 的统一 pre-log/pre-persist seam。

例外：Gateway 普通外部消息已有 `pre_gateway_dispatch` rewrite，可在 gateway 子集早期改写；但不覆盖 CLI/ACP/TUI/cron/subagent/internal event，异常仍 fail-open，不能作为全局安全边界。

## 决策门

- AC1—AC7、AC10（非架构门禁）全绿且用户拍板 AC8/AC9 方案后，方可进入 M2 文件后端。
- 任一外发链路绕过插件，或异常注入时原请求仍外发：停止 M2，重新评估最小 Hermes 核心补丁或本地模型代理。
- AC9：在用户拍板“接受本机可信边界 / 仅披露残余风险”或“Hermes 核心补丁 / 零明文”前，architecture gate 按零明文保持红灯。
