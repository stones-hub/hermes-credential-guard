# M3.1 双文件边界与外发守卫收口方案

> 状态：C 轮完成；0.3.1 候选已形成（见 `docs/M3-验收报告.md`）。本里程碑不安装或升级 worker Profile。
>
> 版本目标：0.3.1（已构建）。

## 1. 已确认产品模型

```text
credentials.json = 本地秘密库
targets.json     = 本地目标目录
外部模型只接触业务 target 名称
```

两个文件继续保留，职责不得合并：

- `credentials.json` 保存真实凭据。可信的本地外发守卫可以读取它，只用于建立脱敏快照；本地执行器只有在 Hermes 标准人工审批通过后，才解析本次 target 对应的凭据并连接目标系统。
- `targets.json` 保存业务 target 到本地执行信息的映射。Credential Guard 内部可读取；外部模型不得通过普通文件/搜索/终端工具整份读取。
- 模型工具参数继续只有 `target + action`，不得新增 host、port、database、credential_ref、username、password、ssh_alias、连接串或自由命令。

### 1.1 审批边界的准确口径

M3.1 后不再宣称“审批前整个进程从未打开 credentials.json”，因为可信外发守卫必须提前知道秘密，才能阻止秘密外发。

准确边界改为：

```text
审批前：
- 可信外发守卫可读取本地秘密库，仅生成本次外发使用的内存脱敏快照；
- 执行器不解析本次 target 的执行凭据；
- 不连接 MySQL/SSH，不执行目标动作。

审批拒绝/超时：
- handler 不调用；
- execution secret resolution = 0；
- MySQL connection / SSH subprocess = 0；
- 不产生目标系统副作用。

审批通过：
- handler 按 credential_ref 只解析本次目标所需凭据；
- 目标系统权限仍由 MySQL GRANT / SSH 本身决定；
- 结果回流前再次使用新鲜脱敏快照处理。
```

本机日志/state DB/WAL 明文仍属已接受的可信宿主残余风险；M3.1 不扩展为本地零明文平台，也不修改 Hermes 核心。

## 2. 当前核心缺口

### G1：生产文件秘密库没有接入外发注册表

当前生产 `register(ctx)` 只注册 middleware/hooks/tools；生产运行时的内存 registry 默认为空。真实 JSON 秘密只有 handler 在审批后执行时才读取。测试 E2E 的 registry 值由测试 companion 注入，因此没有证明生产 `credentials.json` 能保护模型外发。

### G2：本地目标目录可被普通工具整份读取

当前敏感路径规则保护 `credentials.json`，没有保护 `targets.json`。该文件含 MySQL 地址/库名/credential_ref 和 SSH alias，违反“外部模型只接触业务 target 名称”。

### G3：明确直接读取与结果二次保护不完整

`cat $HOME/.ssh/config`、`${HOME}`、`$HERMES_HOME` 等明确路径没有受控展开；terminal/execute_code 的工具结果没有复用同一条命令参数门禁。

### G4：常见可逆表示保护不完整

已登记秘密和私钥 PEM 的 URL 编码、Base64、JSON 转义等常见形式可能穿过最终 Provider 边界。

### G5：验收门禁存在假绿/跨版本误比

- M3 deny/path-block evaluator 没有把所有关键异常字段纳入退出码。
- 发布测试把 M2 历史 0.2.0 哈希与当前 0.3.x manifest 比较。
- 当前全量基线为 `1 failed, 390 passed, 2 xfailed`，不能继续保留“391 passed / PASS”的现状断言。

## 3. 实现原则

1. **独立插件，不改 Hermes 源码。**
2. **TDD：每个缺口先写失败测试，真实看到 RED，再写最小实现。**
3. **外发最终边界 fail closed。**秘密库不可读、权限错误、JSON 错误、快照构建失败、编码扫描失败时，Provider 调用次数必须为 0。
4. **每次外发使用新鲜、独立的 registry 快照。**不在共享全局 registry 上原地 `clear()+register()`，避免并发请求看到半成品；文件很小，安全优先于缓存优化。
5. **不把真实秘密写进异常、日志、审批文案、测试名或报告。**测试仅使用运行时生成的合成 canary。
6. **不增加万能 DLP。**只覆盖本轮明确承诺：已登记秘密的常见确定性表示、私钥 PEM 的有界规范化扫描、标准文件工具和明确直接读取。
7. **外部模型不新增目标枚举接口。**目标目录仍只由本地工具按模型提交的业务 target 精确解析。
