## 1. 本里程碑要解决的问题

R2 只实现最终流程中的三个环节：

```text
模型提交结构化请求
        ↓
本机生成不含真值的 InjectionPlan
        ↓
Hermes 标准人工审批
        ↓
本机复核并一次性消费计划
```

R2 要证明：用户批准的正是随后准备执行的那一次调用；配置、目标、凭证引用、工具或参数发生任何变化时，旧审批不能继续使用。

R2 **不读取或注入真实执行凭证，不连接目标，不调用带引用的下游工具**。计划验证成功后仍固定返回 `RUNTIME_ADAPTER_NOT_READY`。HTTP Header、单次环境变量和 stdin 的真实注入属于 R3。

## 2. 与最终目标对齐的术语

四个概念必须分开：

| 概念 | 含义 | 模型是否可见 |
|---|---|---|
| credential | 逻辑凭证记录，如 `jenkins-token`；真实值只在本机配置中 | 只看见逻辑名称，不看见真值 |
| target | 业务目标，如 `jenkins-production` | 可见业务代号，不必知道真实 host |
| binding | 本机安全绑定；规定 target 可使用哪个 credential、工具、协议和注入位置 | 只需知道业务代号；完整规则留本机 |
| InjectionPlan | 当前一次调用的不可变使用计划，不含真值 | 不发送给模型；审批只展示安全摘要 |

逻辑引用格式：

```text
<CREDENTIAL:jenkins-token>
```

其中 `jenkins-token` 是 credential 名，**不是 binding 名，也不是 target 名**。

最终 Jenkins 语义保持：

```text
target: jenkins-production
method: POST
path: /job/project-x/build
credential: <CREDENTIAL:jenkins-token>
```

本机必须核对：`jenkins-production` 对应的 binding 确实绑定 `jenkins-token`，工具、协议和引用位置也与规则一致。

## 3. 结构化引用契约

### 3.1 合法引用

第一版引用必须占据一个完整字符串参数值：

```json
{
  "target": "jenkins-production",
  "credential": "<CREDENTIAL:jenkins-token>"
}
```

### 3.2 一律拒绝

以下形态 fail closed：

- `Bearer <CREDENTIAL:jenkins-token>`；
- URL、Header、query、body、Shell、SQL 或普通聊天中的拼接引用；
- `<CREDENTIAL:...>` 截断、嵌套、大小写混淆或编码变体；
- 未登记 credential；
- 同一调用出现多个引用；
- 引用出现在配置不允许的参数位置；
- `target` 缺失、未知或与 credential 的 binding 不匹配；
- 有引用但缺少 `tool_call_id`、`session_id` 或调用身份不完整。

R2 不做全局字符串还原，也不尝试“猜测模型想用哪个 binding”。如果存在零个或多个可匹配 binding，都失败关闭。

## 4. binding 匹配原则

R2 使用 R1B 在 Provider 外发保护阶段已发布的同代 runtime snapshot（`get_runtime_view()`），只读取 scrubbed binding metadata、逻辑 credential 名与已发布 config identity；**不得**为审批或复核再次 open/read/parse `credential-guard.json`。

匹配必须同时满足：

1. `target` 与业务 binding 名一致；
2. 引用名称与 binding 的 `credential_ref` 一致；
3. `tool_name` 符合该 binding 类型的允许工具；
4. 引用所在参数路径符合结构化契约；
5. binding 的 `approval` 为 `required`；
6. binding、配置摘要和 **config_file_identity** 属于同一已发布配置身份（见下）；
7. 只有一个 binding 完整匹配。

`RuntimeView.generation` 仅为 R1B egress 发布事件观测计数，**不是** R2 安全绑定字段；InjectionPlan 不保存、不校验 `runtime_generation`。同一配置的 fresh publish 会无意义递增 generation，因此安全绑定使用 **published snapshot identity + config/binding/target digest + 当前 lstat**，不得要求“必须绑定 generation”。

准确边界措辞：

- 可信外发保护层（R1B `llm_request` / `llm_execution`）会在 Provider 外发前读取已登记 secrets，目的是保证模型永远看不到它们；
- R2 **不**因工具请求、审批或审批后复核而再次读取/解析本次执行 credential；
- “审批前任何本机组件都从未读取凭证”不是产品目标，也与 R1 外发保护不可兼容；
- “审批前不读取本次执行所需凭证”指执行解析边界（R3），不禁止可信外发保护层预加载/建立脱敏 registry。

历史假绿（已推翻，不得再声称）：第一轮 P6 引入的 `runtime_metadata.py` “metadata-only parser”仍会 `_open_and_read` 整份单文件并访问 `value`/`username`/`password` 字段；已删除该模块。R2 正确路径是复用已发布 scrubbed snapshot，另仅允许 `Path.lstat()` 比较 inode/device/mtime/size。

plan 中的 `config_digest` 来自已发布 `RuntimeView`（R1B 完整配置摘要）。凭证轮换与文件替换由 **当前 lstat 身份变化** 阻断；R2 不重新解析文件。重新完成 R1B Provider 发布后才会得到新 snapshot 和新调用。同 mtime/size 原位改写属于可信本机用户边界，不升级为 OS DLP。

R2 只验证绑定关系，不承诺该 adapter 已可执行。R3 才在 plan 复核成功后，通过单凭证最小解析 API 获取本次执行所需真值。

## 5. InjectionPlan 数据模型

计划使用不可变结构，至少包含：

```text
session_id
turn_id
tool_call_id
tool_name
args_digest
reference_arg_path
credential_name
target_name
binding_name
binding_type
config_digest
binding_digest
target_digest
config_file_identity
nonce
created_monotonic
expires_monotonic
state
```

约束：

- 不保存 token、password、Basic Auth、Header、stdin 真值或任何可逆派生值；
- 不保存完整原始参数正文；
- 不保存 `runtime_generation`（generation 仅作 R1B 观测，不作 plan 安全字段）；
- `args_digest` 基于严格 canonical JSON：键排序、数组顺序保留、拒绝 NaN/Infinity 和不支持类型；
- `target_digest` 绑定本机目标规则，但审批文案只显示业务 target 名；
- `config_digest` 取自已发布 RuntimeView；轮换/替换检测依赖当前 lstat 与 plan/published identity 对齐；
- `config_file_identity` 只使用 inode/device/mtime/size 等身份元数据；
- plan key 至少绑定 `(session_id, tool_call_id)`；带引用调用三阶段均要求非空 `session_id + turn_id + tool_call_id`；不得用线程 ID 兜底；
- plan TTL 必须来自 Hermes 可信只读 `_get_approval_timeout()`（或已实测等价公开接口）加固定复核余量；分数超时使用 `ceil(timeout)`，避免 `int()` 截断使 plan TTL 短于宿主审批窗口；读取失败、类型非法、非正数、非有限值或超过显式安全上限（`MAX_APPROVAL_TIMEOUT_SECONDS=86400`，Hermes `approvals.timeout` 无 schema 上限）时带引用调用 fail closed，不得静默回落固定 300 秒；
- nonce 使用密码学安全随机数；
- 状态只允许单向变化：`ANALYZED → APPROVAL_PENDING → CONSUMED`，异常进入 `INVALIDATED`；
- `CONSUMED` 或 `INVALIDATED` 永不可恢复、不可复用。

## 6. 三阶段行为

### 6.1 tool_request：只分析，不读真值

职责：

1. 深拷贝参数；
2. 识别严格引用；
3. 使用 **已发布** runtime view（`get_runtime_view()`）匹配 binding；不重新 load、不构建 egress registry；
4. 生成并保存 InjectionPlan（含 published identity）；TTL 来自 Hermes approval timeout + 复核余量；
5. 返回参数时仍保留逻辑引用，不注入、不改写真值；
6. middleware trace 只返回固定 `source/reason/name`，不返回 plan、摘要明文或配置详情。

无引用调用：参数保持语义和结构等价，不创建 plan。runtime 未发布时，带引用 fail closed；普通无引用继续非干扰。

内部异常：记录当前调用为 fail-closed；不得裸抛后依赖 Hermes，因为 R0 已证明宿主会吞掉裸 middleware 异常继续。

### 6.2 pre_tool_call：生成一次性人工审批

职责：

1. 保留 R1B 的敏感路径阻断逻辑；
2. 对无引用普通调用不增加审批；
3. 对带引用调用查找并重新核对 plan（要求 session+turn+tool_call）；
4. plan 缺失、异常、过期或身份不一致时直接 block；
5. 用已发布 view + 当前 **lstat** 比较 identity（不 open/read 配置正文）；身份变化 block，要求重新发起调用；
6. 返回 Hermes `approve` 指令和一次性 `rule_key`。

审批文案只显示模型本来已知或用户需要判断的安全信息，例如：

```text
Credential Guard 请求使用本机凭证
工具：http_credential_request
业务目标：jenkins-production
逻辑凭证：jenkins-token
操作：POST /job/project-x/build
注入方式：HTTPS Authorization Header
审批范围：仅本次调用
```

不显示：真实凭证、Authorization、真实 host（若模型只知道业务别名）、配置路径、完整配置、完整 body、内部异常栈。

内部绑定使用的 `rule_key` 包含：

```text
nonce + tool_call_id + tool_name + args_digest + config_digest + binding_digest
```

每次新调用都会产生新 nonce。即使 Hermes UI 保存了 session/always 选择，也只保存这一个随机 key，不能自动批准下一次调用。

### 6.3 tool_execution：审批后复核，但仍不注入

可信前提：Hermes 标准审批控制流可信；拒绝或超时不会进入 tool_execution。

职责：

1. 对无引用普通调用，`next_call` 原样且仅调用一次；
2. 对带引用调用，在本进程共享锁临界区内：最终 lstat → 比较 published snapshot + plan → consume；不得在临界区外另行重读配置；
3. 比较 session、turn、tool_call、tool、参数摘要、引用路径、target、credential、binding、配置摘要与 identity；
4. 任一变化：原子标记 plan 为 `INVALIDATED`，不读具体 secret、不调用下游；
5. 全部一致：原子把 plan 标记为 `CONSUMED`，仍不解析真值、不调用下游；
6. 固定返回安全错误 `RUNTIME_ADAPTER_NOT_READY`。

消费动作必须发生在返回固定错误前，确保同一审批不能第二次使用。R3 将来解析/注入必须延续同一临界区。

## 7. 审批姿态与可信宿主边界

最终目标要求每次真实凭证使用都经过人工审批，同时明确“不做第二套审批系统”。因此：

- 复用 Hermes `pre_tool_call → request_tool_approval`；
- R2 不创建审批票据、审批数据库或新 UI；
- 正式受保护运行要求 `approvals.mode: manual`；
- YOLO 或明确关闭审批时，带引用调用必须 block；
- 普通无引用工具不受影响；
- 若插件无法通过稳定接口确认 manual/YOLO 姿态，R2 判 BLOCKING，不以猜测或读取真实 worker 正文绕过。

编码前先在临时 HERMES_HOME 中做宿主姿态 spike，确认可复用的读取接口与实际行为。不得修改 Hermes 核心。

## 8. TOCTOU 与重放矩阵

必须阻断：

- 审批期间修改 `credential-guard.json`（lstat identity 变化）；
- 凭证轮换导致文件身份变化（R2 不重新解析；轮换由 lstat 阻断，需重新完成 R1B 发布才有新 snapshot）；
- target、credential 引用或 binding 关系变化（相对已发布 snapshot）；
- tool、method、path、query、body 或其他参数变化；
- 引用从一个 arg path 移到另一个；
- 更换 session、turn 或 tool_call_id；
- 复用已消费 plan；
- 两个并发调用交叉使用 plan；
- plan 过期；
- plan store 达到上限；
- tool_request、pre_tool_call 或 tool_execution 任一内部异常；
- lstat→consume 竞态（第一次身份读取后、consume 前改写配置）。

每个反例都必须同时满足：

```text
execution_secret_resolve_count = 0
downstream_call_count = 0
```

## 9. 有界生命周期

R2 先确定原则，不凭空写死 TTL 和容量：

- plan 必须有过期时间和容量上限；
- 时钟使用 monotonic；
- TTL 必须覆盖 Hermes 合法人工审批窗口，并通过临时 Profile 的真实审批链验证；
- 具体 TTL/上限由“宿主审批超时源码事实 + 隔离 E2E”确定后写为显式常量和测试；
- 超限 fail closed，不通过静默淘汰仍有效 plan 来继续执行；
- 每次访问清理已过期/终态 plan；
- session reset/end 能收到稳定 hook 时清理对应 plan；若接口不稳定，不把该增强当安全前提。

## 10. fail-closed 设计

Hermes 当前会吞掉插件裸异常并继续，所以三个阶段都必须插件内捕获：

| 阶段 | 安全行为 |
|---|---|
| tool_request 异常 | 保留引用参数、登记调用为 invalid；后续 pre/tool_execution 都阻断 |
| pre_tool_call 异常 | 返回固定 `action=block` |
| tool_execution 异常 | 不调用 `next_call`，返回固定安全 JSON |

任何错误结果都不得包含：原始参数、路径、host、credential 名以外的秘密元数据、摘要全值、异常正文或 traceback。

## 11. 兼容与非干扰

R2 必须保留：

- R1B 的 read_file/search_files/terminal/execute_code 敏感路径门禁；
- R1B 的 Provider 外发与结果脱敏；
- R5 前旧 MySQL/SSH 固定动作的历史兼容行为，不在 R2 顺手删除；
- 无引用的普通聊天、编码、文件、Git、terminal、SSH Config、Docker/systemd 和日志排查能力。

R2 不改版本、不构建制品、不覆盖 `dist/`、不安装正式 worker。

## 13. 验收红线

1. 审批前 execution secret resolve = 0；
2. 拒绝、超时、异常：secret resolve = 0，downstream = 0；
3. R2 批准路径：secret resolve = 0，downstream = 0，固定 adapter-not-ready；
4. approval、trace、stdout/stderr、共享 state 中真值及连续片段计数为 0；
5. target/credential/binding 不匹配全部阻断；
6. 所有 TOCTOU、重放、过期和并发交叉反例阻断；
7. manual 不成立或 YOLO 启用时引用调用阻断；
8. 无引用普通工具行为不变，`next_call` 恰好一次；
9. R0、R1A、R1B 专项与全量测试 0 failed（AC8/AC9 保持既定 xfail）；
10. compileall 通过；
11. worker 基线无漂移；
