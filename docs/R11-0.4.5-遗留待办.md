## 待办 1 —— 配置报错路径检查，两个分支未覆盖

**位置**：`credential_guard/config.py` 的 `_assert_secure_parent_dir()`（约 352-373 行）

**复审证据**：

| 变异 | 分支 | 测试反应 |
|---|---|---|
| MUT8 | 父目录 `stat` 失败 | 全绿（**未抓住**） |
| MUT10 | 父目录是软链接 | 全绿（**未抓住**） |
| MUT8b | 配置文件本身 `stat` 失败 | 转红（已覆盖） |
| MUT14 | `CONFIG_PARENT_INSECURE_MODE` | 转红（已覆盖） |

同类分支，覆盖不均。

**主代理复核后的更正（重要）**：

复审员的措辞是「报错可能暴露完整本机路径」，实测后这条**比该措辞轻**：

- `_assert_secure_parent_dir()` 抛出的 `ConfigError` 消息是写死的 `"configuration error"`，**不含路径**
- 真正拼接路径的是 `credential_guard/middleware.py:403` 的 `f"文件：{path}\n"`
- 而 `middleware.py:187` 的注释明确写着：
  > Everything below writes to stderr only. None of it is ever returned from a ...

即**这段带路径的诊断文本只写本机 stderr，不进入发给模型的请求**。

**所以真实性质**：不是外发泄漏风险，而是「一条防泄漏的规则缺少测试承重」。

**建议修法**：对所有 `ConfigError` 抛出点加一条统一的参数化断言 —— 消息中不得包含 `str(path)`。
覆盖全部错误码分支，而不是逐个补。

## 待办 2 —— config 层凭证最短长度校验无测试承重

**位置**：`credential_guard/config.py:202`

```python
if not allow_short and len(value.strip()) < MIN_SECRET_LENGTH:
```

常量定义在 `credential_guard/registry.py:8`（`MIN_SECRET_LENGTH = 8`），config 层 import 使用。

**复审证据**：MUT13 删掉该行下限校验后 —— 窄集 126 passed、宽集 310 passed，**全绿**。

**为什么是问题**：同一规则两处实现，只有一处被盯住。

| 层 | 是否有测试承重 |
|---|---|
| `registry` | 有（`test_redactor`、`test_token_invariants`） |
| `config` | **无** |

**后果**：该行被误删或改坏后，配置里写 1 位数的凭证值也能通过校验，且无任何测试报警。

**建议修法**：给 config 层加一条测试 —— 配置中放一个短于 `MIN_SECRET_LENGTH` 的凭证值，
断言加载被拒（且断言的是 config 层路径，不是 registry 层）。

## 待办 3 —— 路径归一化 fail-closed 分支无测试承重

**位置**：`credential_guard/sensitive_paths.py:515-518`

```python
try:
    path = _normalize_path_input(raw_path)
except Exception:
    return True  # fail closed on weird input
```

**复审证据**：MUT9 把 `return True` 改为 `return False`（即「看不懂就放行」）后 ——
窄集 76 passed、宽集 151 passed，**全绿**。

**复审员同时实测的缓解事实**：该分支近乎不可达。`_normalize_path_input` 几乎不抛异常，
独立探针只在 `~\x00`（含空字节）这类输入上触发 `ValueError`。

**所以真实性质**：当前行为正确（看不懂就当受保护，是正确的 fail-closed），
只是缺一条测试证明它。复审员自己的建议原话是「补一条针对性用例而非视为缺陷」。

**建议修法**：加一条用 `~\x00` 等无效输入的用例，断言 `path_is_protected()` 返回 `True`。
