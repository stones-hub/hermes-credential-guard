# R10 / 0.4.4 协议字段已登记凭证失败关闭修复方案

## 大白话

协议骨架字段（`model` / `role` / `name` / `tool_call_id`）的 value 如果直接放进了已登记凭证（或其受支持变体），不能再悄悄替换成逻辑 token 后继续发给 Provider。必须本机 fail-closed：Provider=0，canonical Session 不变，阻断提示不回显合成明文。

0.4.3 已对「边界未知编码私钥」在协议字段上 fail-closed；本轮补上对称缺口：已登记凭证变体命中协议字段 value。

## 问题

`redact_payload` 递归替换所有字符串 value。`_CORE_PROTOCOL_KEYS` 只保护 dict **key** 不被改写，不保护上述四个字段的 **value**。结果：合成已登记凭证放入协议字段 → 变成 `<SECRET:…>` → Provider=1。无明文泄漏，但违反协议完整性与文档宣称的「协议字段 Provider=0」。

## 设计要点

| 主题 | 行为 |
| --- | --- |
| 判定时机 | 在 `redact_payload` 替换成 token **之前**，对 Provider-bound 副本做结构 path 判定 |
| 封闭 allowlist | 仅 `request.model`、`messages[i].role` / `.name` / `.tool_call_id` 的 string value |
| 命中语义 | 与 residual 一致：任一受保护 variant 出现在该 value 中 → `RequestBlock` |
| 原因码 | 复用 `CG-RESIDUAL-SECRET`（固定安全结构；不拼字段原值/工具名/host/异常正文） |
| 内容类字段 | `messages[*].content`、`tool_calls[*].function.arguments` 仍替换为稳定逻辑 token 后 Provider=1 |
| 不复用 | 不得把 PEM whole-field fallback allowlist 当作协议字段注册凭证规则 |
| 仅副本 | 永不改写 canonical Session |
