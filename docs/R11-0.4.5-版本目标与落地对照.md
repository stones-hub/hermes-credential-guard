# R11 / 0.4.5 —— 版本目标与最终落地对照

**这份文件是 0.4.5 的「要解决什么问题」记录**，并已按**实际发布的代码**校订。
原方案写于开工前（2026-08-20），中途有两处方向变更（C1 撤回、迁移器删除），
本文正文已改写为与 v0.4.5 实际代码一致的表述，不保留会误导人的旧承诺。

- 发布版本：**v0.4.5**（首个正式发布版本，commit `7d4644c`）
- 遗留未做项：`docs/R11-0.4.5-遗留待办.md`
- 验收读数与复审结论：`docs/R11-0.4.5-验收报告.md`、`HANDOVER.md`

---

## 一、为什么做这一版

0.4.4 的安全能力实测扎实：已登记凭证六种编码形态全部防住、注入全程审批、
越界全拒、回流双向脱敏。

但**产品此前是按「作者自用」打磨的，不是按「陌生人开箱」打磨的**。三类问题：

| 类别 | 后果 |
|---|---|
| 装完即砖 | 新用户装完插件、还没建配置，整个 Hermes 不能聊天 |
| 安全错觉 | 用户以为「装了就安全」，实际只保护手工登记过的凭证 |
| 失败不说话 | 所有错误塌缩为两个不说明原因的出口，其中一个名字还在撒谎 |

目标：**让没读过源码的人装上插件后，知道自己被保护了什么、犯错时知道怎么改。**

### C1. 零配置行为 —— **本版最大的方向变更**

**原方案**：配置目录不存在时放行，让新用户先能聊天。

**实际发布**：**撤回该放行，未配置一律 fail-closed 阻断。**

变更原因：C1 原设计依赖「猜配置目录在哪」，而猜的依据是 `HERMES_HOME`
环境变量。这条路径历史上已导致三次凭证泄漏。本版把定位方式改为
**从插件自身安装位置反推 profile 根**（见第三节），一旦定位方式确定，
「目录不存在 = 未配置 = 放行」这个前提就不再成立：定位失败时无法区分
「用户没配」和「插件算错了位置」，放行就是拿凭证赌运气。

因此最终行为：

| 情况 | 行为 |
|---|---|
| 配置文件存在且合法 | 正常工作 |
| 配置文件不存在 | **阻断**，本地提示期望路径与创建方法 |
| 配置文件存在但非法/权限不对/是软链接 | **阻断** |
| 配置合法但 `bindings` 为空 | 正常工作（只脱敏，不授权执行） |

用户可见提示（`middleware.py` `DIAGNOSTIC_REASONS`）：

```
原因：配置目录已存在，但其中没有 credential-guard.json。
处理：照 README 手工创建该文件（权限 600），再重启 Hermes。
```

### C2. 配置错误给出可操作诊断 —— 已落地

配置加载失败时输出文件路径、结构化 `location`、固定处理建议。

硬约束（均已实现并有测试）：
- 只写本机 stderr，**不进入模型上下文**（`middleware.py` 内有显式注释与门禁）
- 不回显任何凭证值、username、password、header 值
- 非法/超长/含控制字符的 location 降级为固定值 `configuration`

### C3. 修复文档示例 Bug —— 已落地

原 `docs/R3-通用本地凭证注入-落地方案.md` 示例含 `allowed_tools` /
`reference_arg_path` 两个 schema 禁用字段，照抄会导致整个配置被拒。已删除，
并扫过全仓文档确认无同类示例。

### C4. README 头部写死保护边界 —— 已落地

README 开头即声明「保护什么 / 不保护什么」，并补「最小可用配置」章节。

不保护项如实列出：未登记的凭证、自动标题、上下文压缩、图片识别、
session_search 等辅助模型调用。

### C5. 工具描述列出可用目标 —— 已落地（旁车架构）

不在注册时读主配置（那会违反「审批前不读凭证明文」门禁），改为读插件自动生成的
安全旁车 `credential-guard.targets.json`：

- 旁车只存模型可见字段：binding 名、`type`、`credential_ref`、HTTP
  `allowed_methods` / `allowed_paths`
- **禁止**出现 host / port / program / argv / env / header / secret / digest
- 旁车绝不作为执行依据；正式 egress / 审批 / 执行仍走主配置
- 旁车缺失 / 过期 / 权限不安全 / 非法 → 工具描述退化为静态文案，不影响保护

### C6. 引用语法错误明确报错 —— 已落地

把插件自己盖的脱敏代号 `<SECRET:cg_…>` 当凭证引用传入时，返回固定错误
`CREDENTIAL_CODE_NOT_USABLE`，而不是含糊的通用失败。

只改错误信息，**不改变放行/阻断判定**；不得由代号反查真实凭证名。

### C7. 未登记凭证提示（不拦截）—— 已落地

识别常见凭证前缀（`sk-`、`ghp_`、`AKIA`、`xoxb-`）时打一行本地提示。

硬约束：放行行为零变动、只写本地、不输出被检测内容本身（连片段和哈希都不输出）、
检测器异常时静默跳过、每 session 同形态最多提示一次。

**诚实性**：该检测注定不完整，纯随机串认不出。README 与提示文案均表述为
「可能遗漏」，不作为兜底能力宣传。

### C8. 错误码更名与死代码清理 —— 已落地

`RUNTIME_ADAPTER_NOT_READY` 字面意思是「适配器未实现」，但适配器均已实现，
该码曾被用于所有引用路径出口，主动误导诊断。已删除，改为如实反映原因的
`REFERENCE_PATH_BLOCKED` / `CALL_IDENTITY_REQUIRED` / `PLAN_NOT_FOUND` /
`PLAN_NOT_PENDING` / `PLAN_RECHECK_FAILED`。

### C9. 统一两条路径占位符 —— 已落地（保守统一）

两条路径均输出 `<SECRET:cg_[0-9a-f]{16}>`。

**不**统一成 `<CREDENTIAL:name>`：用户粘贴进主请求的内容不得被升级成
模型可执行的逻辑引用。

### C10. 离线配置校验命令 —— 已落地

`hermes credential-guard validate [file]`：逐条输出 PASS/FAIL，
不联网、不调 Provider、不生成旁车、不写任何文件。

## 三、开工时未列、中途新增的两项重大改动

### 改动一：配置位置改为从安装路径反推（**本版真正的地基**）

**问题**：插件靠 `HERMES_HOME` 环境变量猜配置在哪，且仓库里有三份各自为政的
猜路径实现。历史上因此泄漏过三次。

**改法**：新增 `credential_guard/store_location.py` 作为**唯一真相源**，
从插件自身安装位置上推 profile 根。三份重复实现删除。

**收益**：多 profile 各自装插件时，各自读各自的配置，互不串台。

**实测**：`HERMES_HOME` 取【不设 / 指向别的 profile / `/tmp` / 空串】四种值，
解析出的 store 位置恒定不变。

### 改动二：删除整套 v1 双文件迁移器（破坏性）

**删除对象**：`credential_guard/migration.py`（约 2200 行）、CLI 的
`migrate-config` 子命令、`tests/test_config_migration.py`（70 条）等。

**理由**：0.4.5 是第一个正式发布版本（0.3.1 / 0.4.0 / 0.4.4 均未打 tag、
未发 Release），**不存在持有 v1 双文件格式的用户**。迁移器服务的用户群为空，
留着反而是第四份「猜配置路径」的实现。

**代价**：不再提供 v1 → v2 自动迁移，如遇 v1 配置只能照 README 手工重建。

## 四、明确不做（本版边界）

| 提议 | 拒绝理由 |
|---|---|
| 覆盖自动标题 / 压缩 / 视觉 / session_search 等辅助调用 | 纯插件接口拿不到这些出口，Hermes 侧未开放；如实写入不保护清单 |
| 把未登记凭证检测做成兜底 DLP | 纯随机串检测不出，宣传为兜底就是制造安全错觉 |
| 由脱敏代号反查真实凭证并自动替换 | 等于代号还原，明确禁止 |

## 六、本方案修正的历史错误结论

- 「零配置放行更友好」→ 在定位方式不可靠的前提下，放行等于拿凭证赌运气，已撤回。
- 「迁移器必须一直维护」→ 服务对象为空时，维护它只是在增加攻击面。
- 「测试全绿即安全」→ 本版中一次桥接缺陷让测试写进了操作员真实 profile，
  全绿掩盖了它；结论：任何「安全」读数必须先证明反向能报错。
