## 12. 第五轮窄修 — 配置发布/写入与最终消费共享锁协议（追加）

> 日期：2026-08-03  
> 触发：冻结候选最终独立安全复审 BLOCKING — `_EXECUTION_RECHECK_LOCK` 下 `lstat→consume` 窗口与 R1B publish / migration writer 无同一跨进程协议（见 `.r2-config-lock-race-fix-task.md`）  
> 判定：**协作竞态 blocker 已关闭（待主代理独立复验签收）**

### 12.1 BLOCKING 关闭项

| 项 | 修复 |
|---|---|
| 跨进程协议锁 | 新增 `credential_guard/config_lock.py`：`.credential-guard.runtime.lock` + `fcntl.flock`；shared / exclusive；有界超时 fail closed |
| R1B publish | `load_and_publish_runtime` 的 shared lock 覆盖读正文→build→publish 全段 |
| R2 最终消费 | `on_tool_execution` 引用路径 shared lock 覆盖最终 `lstat→compare→consume→adapter-not-ready`；注释明确 R3 resolve/inject/下游启动必须留在同一临界区 |
| 正式 writer | `migrate_config` 在 migrate flock 之后对统一单文件写事务持 exclusive；正式 helper `exclusive_atomic_replace_config` 供协作写入/并发测试 |
| 敏感路径 | `.credential-guard.runtime.lock` 加入 `_STORE_BASENAMES`；普通 `app.lock` 不误伤 |

锁顺序（禁止反转）：

```text
跨进程 config lock → runtime / execution in-process lock → plan store lock
migrate flock（仅 writer）→ exclusive config lock
```

### 12.2 语义说明（非 INVALIDATED）

协作锁下，配置轮换被序列化到本次批准调用临界区之后：本次 plan 可 **CONSUMED**；writer 在 shared 释放后才完成；下一次 R1B publish 读到新完整配置。不要把“writer blocked”误写成 `INVALIDATED`。

威胁模型保持：仅约束 Credential Guard 正式 publish/write/consume 协作路径；**不**声称阻止恶意同 UID 进程绕过协议直接 syscall 改文件。

### 12.3 Production writer 清单（不虚构）

| 路径 | 角色 |
|---|---|
| `migration.migrate_config`（含 recovery/rollback 写阶段；CLI `migrate-config`） | 唯一正式统一单文件事务 writer |
| `config_lock.exclusive_atomic_replace_config` | 正式 exclusive 原子替换 helper（测试与未来协作写入） |
| CLI init/setup | **无**统一配置创建/覆盖 production writer |

### 12.4 tool_call_id 覆盖线索（仅分类，未改代码）

`InjectionPlanStore.put()` 会覆盖相同 `(session_id, tool_call_id)`。核实结果：

- 新 plan 经 `create_analyzed_plan` **总是**生成新 ≥128-bit nonce；
- `_reference_rule_key` 绑定 nonce → **新 rule_key**；
- Hermes session/always 以 `rule_key` 为粒度，旧批准无法命中新 key。

结论：**非 blocker**；不扩修。
