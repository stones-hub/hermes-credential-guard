# R8 / Credential Guard 0.4.2：HTTP 与 HTTPS 统一凭证请求方案

> 状态：方案已由用户于 2026-08-12 确认，进入严格 TDD 实现。

## 一、业务目标

现有 `http_credential_request` 只接受 HTTPS。内网接口测试经常使用 HTTP，用户需要 Hermes 在模型看不到真实凭证的前提下，经人工审批后向固定内网 HTTP 接口注入 Bearer、Basic 或 API Key Header。

本里程碑将现有 HTTP binding 的 `target.scheme` 从“仅 `https`”扩展为“精确接受 `http` 或 `https`”。不新增第二套执行器，不新增 CIDR、`network_policy`、全局危险开关或业务动作。

## 二、统一执行模型

两种 scheme 共用同一条受控链路：

```text
结构化逻辑引用
→ 固定 binding 匹配
→ 人工审批
→ 摘要、参数与配置身份复核
→ 审批后本机解析真实凭证
→ 按 scheme 选择 HTTP/HTTPS transport
→ 禁代理、禁重定向、deadline、响应上限
→ 统一结果守卫脱敏后回模型
```

差异仅在传输层：

| scheme | 传输行为 |
|---|---|
| `https` | TLS 加密；系统信任链；校验主机名 |
| `http` | 明文传输；不使用 TLS；审批信息必须明确提示风险 |

不得在 HTTPS 失败后自动降级到 HTTP。

## 三、配置契约

合法目标：

```json
{"scheme":"https","host":"api.example.test","port":443}
```

```json
{"scheme":"http","host":"internal-api.example.test","port":8080}
```

仅接受精确小写字符串 `http`、`https`；`ftp`、`file`、`ws`、大小写变体和其他值继续 `CONFIG_SCHEMA` fail-closed。规范化输出必须保留原 scheme。

其余字段、闭集 Schema、host/port、method、精确 path、inject 和 approval 规则不变。

## 四、安全边界

1. scheme 必须进入 `binding_digest` 和 `target_digest`；HTTP/HTTPS 互换会使批准失效。
2. host、port、method、path、credential、inject 和所有限制继续绑定。
3. HTTP/HTTPS 都禁止环境代理和自动重定向。
4. HTTP/HTTPS 都执行相同的 connect timeout、total deadline、响应大小限制和 Header 处理。
5. 两种 scheme 都只能在审批后解析并注入凭证；拒绝、超时、重放和偷换均为零次下游执行。
6. HTTP 审批固定提示：`警告：该目标使用明文 HTTP，凭证在网络传输过程中不会被加密。`
7. 审批、日志、模型上下文与结果中不得出现真实凭证。
8. 测试只用合成诱饵、临时 HOME/HERMES_HOME、loopback HTTP/TLS 服务；不得读取真实配置、真实凭证或连接真实内网目标。

## 六、严格 TDD 验收矩阵

1. Schema 接受 HTTP 与 HTTPS，拒绝其他 scheme。
2. HTTP Bearer、Basic、API Key Header 分别使用合成凭证完成真实 loopback 请求。
3. HTTP 请求的 URL、method、path 和 Header 与 binding 一致。
4. HTTP 不使用环境代理、不跟随 3xx。
5. HTTP connect timeout、total deadline、正常及 HTTPError 慢响应、响应超限均 fail-closed 或按既有安全语义处理。
6. HTTP 结果回显合成凭证时经统一结果守卫脱敏。
7. HTTP 拒绝、审批超时、重放、参数偷换和 scheme 偷换均不得执行下游请求。
8. HTTP 审批有明文风险提示；HTTPS 无该提示；两者均不显示真实 host、Token、密码或 Header 值。
9. HTTPS 原有 TLS、系统信任链、主机名校验、禁代理、禁重定向和 deadline 测试不回退。
10. mutation 门禁至少能检出：重新写死 HTTPS、丢失 scheme digest、HTTP 走环境代理、HTTP 跟随重定向、HTTP 绕过 total deadline、HTTP 缺风险提示。
11. 专项、历史回归、全量非构建 pytest、compileall、拓扑门禁全部退出码 0。
12. 版本统一为 0.4.2；双构建字节一致；新制品只以版本化名称与历史制品共存；隔离安装 ZIP E2E 通过。
