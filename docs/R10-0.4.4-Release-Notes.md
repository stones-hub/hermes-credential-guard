# Credential Guard 0.4.4 Release Notes

## Highlights

- Protocol skeleton field values (`model`, `role`, `name`, `tool_call_id`) that contain a registered credential variant now fail closed locally (Provider=0).
- Content-class fields continue to tokenize registered secrets and proceed (Provider=1) on the Provider-bound copy only.
- Canonical Session remains untouched; block carrier / user prompt / logs never echo synthetic plaintext, tokens, or derived hash/length metadata.

## Fixes

- Narrow hardening for registered secrets in protocol-field **values** (0.4.3 already covered boundary-unknown encoded private keys on those fields).
- Independent closed path allowlist — not reused from PEM whole-field fallback.
- Release artifact-manifest entries now bind exact integer `size` to on-disk `st_size` (in addition to filename + sha256); verifier fail-closes on size drift.

## Security invariants

- Real secrets stay in the local protected store.
- Manual approval remains required before local credential injection.
- No second observability permission catalog; target-system permissions remain the source of truth.
- Synthetic/decoy values only in tests and examples.
